## Distilled takeaway

He is not a novice thinker — he is a **systems thinker without software vocabulary**. The right move is not to dumb down, but to:

1. Map software concepts onto systems concepts (parts, boundaries, flows, state)
2. Layer information deliberately
3. Name terms only when needed, always with a plain definition first
4. Make relationships explicit
5. Stop early

"Necessary information" is a hard constraint, not a soft preference. Default is lean.
