# Translator diary

Persistent notes on how Talha thinks, learns, and communicates — used to personalize technical explanations about Holodeck (and related work) in this chat.

## How agents should use this

1. **Read `profile.md` first** before translating anything non-trivial.
2. **Run answers through the profile layer**: same facts, different framing — match depth, metaphor style, and pacing to what is known to land.
3. **Append to `entries/`** when new signals appear (explicit preferences, reactions to explanations, corrections, calibration choices).
4. **Distill into `profile.md`** when a pattern stabilizes across entries. Keep the profile short; move history to entries.
5. **Mark uncertainty** in the profile when guessing. Do not invent preferences.

## What belongs here

- Communication preferences (depth, tone, metaphor families, anti-patterns)
- Mental models the user already uses
- What clicked vs what fell flat
- Explicit corrections ("don't explain it that way")

## What does not belong here

- Project facts (those live in `docs/`, code, workboards)
- Session transcripts
- Speculative psychology

## Structure

| File / folder | Role |
|---------------|------|
| `profile.md` | Living distilled model — the personalization layer |
| `vocabulary.md` | Terms introduced: plain-language anchor → technical term |
| `entries/` | Chronological diary of observations and updates |
| `README.md` | This file |
